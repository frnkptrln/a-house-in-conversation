# Local memory repair — 10 October 2026

Two failures were reproduced against `87dffaa`: a stored `null` visit record
stopped the threshold with an exception when it looked up the Conversation
Room; a `null` entry in the Archive's fragment pool stopped that room while
loading. Valid JSON is not necessarily the record shape these readers need.

The shared reader now accepts visit maps and treats other shapes, malformed
JSON, and unavailable storage as absent memory. Reading does not write or erase
anything. Rooms still save at their existing visit points, preserving valid
maps, older visit values, and unrelated entries. Afterimage still leaves its
trace at the end of its performance.

The Archive validates each stored fragment's room, integer source index, and
remaining strength. It keeps valid fragments at their existing strength and
keeps the `seen` map, so old visits do not refill already-spent text. Invalid
fragments are omitted when the Archive next saves. An invalid `seen` container
becomes an empty record. No browser-wide clearing or seed reset was added.
